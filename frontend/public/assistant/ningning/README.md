# 宁宁交互素材（2026-10-30）

## 当前：连续动作视频

使用用户交付的四段绿幕视频，原件位于父目录 `.ai-handoff/ningning-video-20261030/generated/`，桌面副本不改动。全部实测为 720×720、24fps；主片 15.04s、悬停片 8.04s、托腮退出 3.04s、思考退出 2.04s。没有升格或放大后声称达到 1024/30。

项目副本由已有 FFmpeg 无损重封装，仅保留主视频流，移除音轨/封面并开启 faststart：`-map 0:v:0 -an -c:v copy -movflags +faststart`。四个 MP4 合计 11,374,014 字节。没有安装依赖、下载模型或调用生成服务。

`ChatCharacter` 解码原视频到 360×360 Canvas，按绿色色差生成 alpha 并抑制边缘绿溢色；不再使用白色/灰色亮度阈值，因此不会按白色抠除鞋面。完整方形画面按同一尺寸显示，不按姿态分别拉伸，也不再叠加静态图片的 CSS 跳跃。

实际检查后的剪辑窗口（秒，非生成任务书目标时间）：

- 默认站立：主片 13.45–14.90。
- 站立→托腮坐姿：主片 0.55–2.40；托腮等待 2.45–4.45。
- 托腮→站立思考：主片 4.55–6.40；思考等待 6.45–9.15。
- 成功回应→跳跃→落地：主片 9.25–13.40；页面入场从 9.80 开始。
- 站立→坐姿指向：悬停片 0.55–2.65；指向等待 2.65–4.45；收手起身 4.55–7.65。
- 托腮退出：退出片 0–2.95；思考退出：退出片 0–1.95。

等待窗口循环，不因时间自动进入回答动作。每段坐下/起身/跳跃先完成，再按最新聊天状态选择下一段；快速回复不会硬切中间动作。失败/取消经对应退出片回站姿，不播放庆祝。悬停中打开聊天先起身，再坐下托腮；打开后的等待姿态优先于悬停。减弱动效偏好或视频解码失败时保留以下透明静态图兜底。播放器实测不等于生成素材完全无形变：部分姿态过渡和跨片衔接仍有生成变形/尺度差，循环接点也不能视为无缝验收。

## 原静态图兜底与历史说明

源图来自用户指定的 `studypilot-参赛材料/2`。原文件保持不变。

- 图一 `out_confused.jpg` → `confused.webp`：发送后至回复完成的挠头姿态。
- 图二 `out_jump.jpg` → `jump.webp`：回复成功完成后跳跃一次，也用于入场。
- 图三 `out_pointing.jpg` → `pointing.webp`：悬停指向姿态。
- 图四 `out_thinking.jpg` → `thinking.webp`：打开聊天、等待提问的托腮姿态。
- 图五 `小助手2.png` → `idle.webp`：默认站姿与动作结束后的姿态。

四张 JPG 用内置 image_gen 工具做透明背景编辑；站姿直接沿用用户透明原图。
提示词共同约束：background-extraction；保留同一人物及原姿态、表情、服饰、头发、双手、双脚和白色鞋面；移除深色背景和独立地面阴影；不裁掉头发、手或鞋；输出真实 alpha。每张另注明原姿态（挠头 / 双手举起跳跃 / 坐姿指向 / 托腮）。生成式编辑可能有细节变化，不声称与原 JPG 像素完全一致。

使用已有 FFmpeg 等比缩放、透明补边并转换为无损 WebP，统一 512×512；五张合计约 921 KiB。项目没有新增依赖。

指向姿态另按 0.824 倍显示，以匹配站姿头部宽度（源图统一画布上分别为 352px 与 290px），底部脚点保持对齐。不能把站姿和坐姿一律撑到同一总高度，否则坐姿头部会突然变大。

接入本轮视频前，页面曾使用透明图及 CSS 呼吸、轻摆、位移和短渐变。这不是骨骼动画，也没有生成姿态之间的真实肢体过渡帧；现已由上述视频播放器替代。

原白底 MP4 与旧白底抠图代码保留供历史参考，当前 ChatCharacter 只对新绿幕视频抠绿。
