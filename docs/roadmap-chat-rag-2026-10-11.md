## 1. 定位与参赛边界

> 2026-10-14 修订：定位由「面向自主学习者的学习助手」改为「AI 微专业能力航图」。下方核心流程、主方向和边界纪律按新定位改写；第 2 节之后的阶段内容仍为 2026-10-12 版本，按新定位推进时逐阶段核对。交接见 `../.ai-handoff/HANDOFF-2026-10-13.md`。

定位：面向在修 AI 微专业 / AI 通识课、非计算机专业、大二到大四、想提升就业竞争力的学生，做就业方向的技能差距诊断与掌握度验证。核心主张是用 AI 检测「完成了任务」和「掌握了知识」之间的差距，不用 AI 替学生完成学习。

核心流程：画像对话 -> 方向推荐与对比、用户拍板 -> 推荐课程（展示课程名、章节、来源）-> 预览并确认学习路线 -> 记录完成情况 -> 测验与讲解验证掌握度 -> 预览并确认调整 -> 更新完成度与掌握度。

- 主方向：场景化轻量 RAG 知识库。做实课程与资料索引、问题相关检索、回答出处，以及检索原文到出题、判分的连接，不把顺序拼接摘录当作完整 RAG。
- 产品价值：个人效能。复用目标、任务、耗时、困难反馈和补救机制，不因此宣称已经实现数字孪生或完整日程冲突调度。
- 亮点：教育可视化。完成度与掌握度分开展示（双环），能力节点按未学 / 完成 / 掌握区分，计划与实际对比。普通进度统计不算知识可视化；掌握度没有测评证据时不显示为已掌握。
- 不扩展为全流程科研助手，不新增多 Agent、社交社区、积分系统、游戏或大规模内容抓取。关卡式测验可以做，但不引入积分、排行榜或养成，文档、界面和参赛材料不使用「游戏」表述。课程与岗位数据离线人工整理后存入 `data/`，抓取脚本不进仓库。

2026-10-11 只读核对的赛事官网接口将这张方向表标为“推荐选题方向”，未发现“必须至少满足一个”的明确条文。用户如另有老师或组委会的要求，按该补充要求执行。选择第 2 项作为主方向不等于官方已确认合规；第 2 项说明中的向量数据库、百科工具和高交互体验需在方案与演示中逐项说明。部分方向名称与说明存在不对应，不能只凭名称承诺符合。

## 3. 推进顺序与建议窗口

日期只是排期建议，不是完成承诺。每阶段以验收门槛为准；失败时缩减可选范围，不跳过必要确认、权限或真实使用验证。

### A. 聊天入口修复，最高优先级

建议窗口：2026-10-12 至 2026-10-15。

先诊断用户原话：“我是一个小白，想学王道数据结构，你帮我推荐规划”。在无规划、有旧规划、有待处理草稿三种状态下记录实际接口、状态事件、耗时和错误代码，再按证据修复。诊断固定覆盖四项风险：(1) 前端 45 秒首事件等待与后端 60 秒上游超时的关系；(2) 调整接口没有进度事件；(3) 普通聊天没有携带多轮历史；(4) 关键词分流误判。四项必须逐一给出证据，不能只改超时文案。

范围：

- 普通聊天发送本会话的有效多轮历史；历史必须按用户和会话隔离，修改或重试后不携带已被截断的后续内容。
- 结合上下文区分普通提问、新学习目标、修改原计划、资料推荐、补充澄清、明确确认或取消。关键词不得单独成为执行重排的依据。
- 模型可以提出意图和建议；实际写入仍由明确动作、目标身份、服务端校验与确认机制决定。识别不清时追问，不自行写库。
- 已明确的“零基础、王道数据结构”先接住，不要求用户重复。只追问当前阶段影响建议或规划的关键信息；正式计划所需约束未齐时不强行生成。
- 用户提供资料后，助手要先分析资料与用户的基础、目标、期限和可用时间；如果现有资料不合适或有更合适的候选，主动提出资料建议，并询问用户是否需要比较。建议说明适配理由和未核实的信息，不编造候选正文、章节、链接或确定的优劣；没有读到内容时只给待核实候选。这个动作只能产生建议，不能自动选择资料、改写规划或写入任务；用户明确确认后，才进入资料比较/选择或计划流程。确认比较不等于确认采用，确认采用也不等于确认写入计划，各动作只授权对应步骤。
- 用户改口或换话题时，不被遗留日期等待或草稿状态无条件截走。
- 无资料也能正常聊天和给一般学习建议；统一实际助手指令与自主学习定位。
- 检查流式响应、心跳或进度、前后端等待预算、停止及重试的生命周期。不能只增大超时或改错误文案就声称解决断连。

验收：

- 原话能进入新目标讨论或必要澄清，不重排旧计划，不直接报笼统网络故障。
- 用户给出资料后，助手能结合资料事实与用户情况提出适配建议；只问“是否需要对比/采用”，未得到确认前不创建选择结果、任务或计划变更。
- “每天背单词有什么技巧”是提问；“把当前计划每天改成 30 分钟”才进入调整建议。
- “刚才第二个方案”“我每天只有半小时”“先不改，解释一下”能接续本会话。
- 新会话和另一个用户没有前一会话的消息、草稿或资料泄漏。
- 四项诊断风险均有可核对记录：45 秒/60 秒等待关系、调整接口进度事件、普通聊天历史请求体、关键词误分流；修复后慢模型、真实上游错误、用户停止和重试各有可核对结果；未确认没有正式变更。
- 阶段范围内包含必要的本地页面验收；真实模型调用需另获批准，平台或环境要求的操作权限仍须遵守。获准后跑一次实际入口的连续对话，保留原始请求链和结果；不控制用户日常 Chrome。此阶段不能仅用注入模型通过收尾。

从 A 阶段开始，每轮与 Cursor 的开发对话、Codex 复审对话和对应验证都要标记：`Prompt 链候选：是/否`、覆盖功能、是否包含问题复现、修复引导和结果。候选标记不等于最终纳入材料；不得把测试构造的 Prompt 冒充真实开发对话。

### B. 小范围轻量 RAG，而非庞大预置资料库

建议窗口：2026-10-16 至 2026-10-22；依赖 A 的聊天入口验收。

先用“数据结构入门”作为演示主题。用户上传是首版主要资料来源；另准备少量已核验、可使用的演示资料。不需要先做全学科资料库，也不复制整本商业教材。

硬标准：评委只按 README，在干净环境、没有开发机隐含状态的情况下，必须能在 10 分钟内启动并完成资料导入与问题检索的最小复现。具备已验证聊天模型配置时，再完成一次带出处回答。向量方案不能依赖评委必须拥有 embedding Key；没有 embedding Key、embedding 服务不可用或配置为空时，必须自动降级到可解释的确定性检索（例如本地词法/全文检索），仍能启动、检索并标明当前检索模式。降级不是静默返回空结果，也不能伪装成向量检索。

没有 embedding Key 不等于没有聊天模型 Key。无聊天模型配置时仍可导入、检索、查看真实摘录及出处，但须明确生成回答不可用，不能用假答案冒充真实模型回答。README 分别写清这两个前提；完整向量路径仍是 B 阶段独立验收项，不能用降级成功代替它。

范围：

- 复用现有文档和片段身份，保留真实的文档名、片段位置与 PDF 页码（有页码时）；没有页码的格式不编造页码。
- 给片段建立向量索引，按本轮问题检索相关片段，再送给模型。实施前评估现有存储和低部署负担的方案，不预先指定新重型服务。
- 明确 embedding 的配置、调用费用、索引更新和删除机制；真实模型调用、重型依赖及迁移单独确认，范围内轻量依赖按 B 阶段授权执行。
- README 必须写明向量路径、无 Key 降级路径、首次启动所需时间、依赖和环境变量；提供没有 embedding Key 的完整复现步骤，并在干净环境实际计时。
- 优先在用户选定范围内检索，不将未选择资料静默加入规划。资料权限在检索和引用读取两端都检查。
- 回答出处来自实际命中片段，可查看原文或定位；不知道时说明依据不足。一般知识建议和资料内结论分开标明。
- 推荐资料的候选目录与正文片段检索分开：元数据可以支持推荐，但不能冒充已读取教材正文。
- 增加一个范围受控的公开参考查询/读取入口，用来补充概念或核实来源，响应失败就说明未核实。不承诺任意网站可读，不做全网爬虫。
- 用户资料和网页内容只作为数据依据，不允许其中的指令获得执行工具、修改计划或访问其他用户资料的权限。

验收：

- 两份内容不同的资料中，按问题找到对应内容，不能永远命中上传顺序靠前的片段。
- 每个资料引用确实对应本次输入的片段；不存在的结论、缺失页码和读不到的网页不造出处。
- 未找到答案时不冒充资料结论；没有任何资料仍可进入普通聊天路径。
- 删除、更新资料后的索引和引用状态一致；不同用户的同名资料不串用。
- 用预先人工标注的小规模问题集评估检索结果和出处，再做获授权的真实模型问答。单纯“返回了向量结果”不算完成。
- 没有 embedding Key 的干净环境能在 10 分钟内跑通降级路径；有 Key 的向量路径另行记录，不把有 Key 的结果当作无 Key 复现证据。
- 演示能看到资料范围、检索依据、检索模式、回答出处及原文查看，不只是在后台调用一个检索接口。

验收：

- 资料中没有的章节不会被包装成来源支持；模型建议的辅助练习明确区别于资料原有内容。
