# 平台余额与自带 Key

平台余额支持学习助手文本对话、学习规划生成/调整、学习诊断、练习生成/判分，统一经过按实际 usage 结算的网关。其他模型能力（图片识题、简历等）暂需切换自带 Key。自带 Key 沿用原请求路径，不扣平台余额。

## 部署与默认状态

本次增加 Alembic 迁移 `b1c2d3e4f5a6`（前驱为 `a4b5c6d7e8f9`）、追加修复迁移 `b2f9e8d7c6a5`，以及积分账本迁移 `c3a1b2c3d4e5`。`b2f9e8d7c6a5` 兼容已经应用早期 b1、但缺少调用单价快照列的数据库，按缺列添加，不重建资金表、不删除历史数据；已有列时保留。历史调用未知单价保持 NULL，不用当前价格补造历史。部署前先备份数据库、完成迁移往返测试，再对目标数据库运行 `backend/.venv/Scripts/python.exe -m alembic upgrade head`（在 backend 目录）。这份说明本身不代表已经对实际数据库迁移。

配置字段见 `backend/.env.billing.example`。配置只在后端读取，禁止放进前端 `VITE_` 变量。默认没有模型、单价、支付身份或密钥，`BILLING_PAYMENTS_ENABLED=false`，目录返回空模型和不可用渠道，不能收款；不使用虚构额度、供应商或价格。

`BILLING_MODELS_JSON` 是对象数组，每项必须包含：

- `id`：平台内部唯一模型标识；`provider`：供应商标识；`displayName`：用户可见名称。
- `model`：供应商实际模型 ID；`baseUrl`：完整 HTTPS OpenAI-compatible `/chat/completions` 地址（无用户密码/查询参数）。
- `inputPricePerMillionYuan` / `outputPricePerMillionYuan`：**用户实际支付**的人民币元/百万 token 十进制字符串，必须由运营方明确配置，不能省略或以供应商成本自动替代。
- `maxInputTokens` / `maxOutputTokens`：正整数上限。单次最大预留不得超过人民币 100 元，否则模型不进入可用目录。

`BILLING_PROVIDER_KEYS_JSON` 是供应商 ID 到后端 API Key 的对象。目录只公开名称、单价和上限，不公开 Key 或请求地址。支持多个供应商/模型，客户端按目录下拉选择。首次启用必须验证供应商真实支持 `max_tokens`、非流式 `choices` 文本、准确且完整的 `usage.prompt_tokens/completion_tokens`（或 `input_tokens/output_tokens`），包括推理输出用量；未兼容的模型不可加入目录。

## 精度、预算与异常

1 元 = 1,000,000 微元（micros），1 分 = 10,000 微元。余额、预留及账本采用整数；费用 = 输入 token × 输入单价 + 输出 token × 输出单价，单位微元，最终合计向上取整到 1 微元；不对两项分别向上取整。

每次请求先按模型配置的输入/输出上限原子预留预算；输入还有 UTF-8 字节长度的保守限制，输出发送 `max_tokens`。提供方实际返回 token 数必须是非负整数且不超过各自上限。成功拿到非空文本和有效 usage 后按实际量扣费并释放剩余预算。每次调用保存所选模型、当时单价、预算、usage 和最终金额。文本取得后若业务解析失败，已经消耗且可核验的模型用量仍会扣费。

余额不足则不调用模型；网络错误、超时、缺失/异常 usage、空响应不扣费并释放预留，不自动重试上游。平台调用采用非流式获取真实 usage 后，再以现有 SSE 协议输出回复，因此首段出现较晚。正常 HTTP 调用超时为 60 秒；进程崩溃留下的预留 10 分钟后，在账户读取或下次调用时通过状态比较更新释放，已释放调用不得再返回付费结果。预留/结算与业务写入使用独立数据库 Session，防止意外提交计划、回答或消息。

## 充值

仅支付宝网页支付和微信 Native。后端最低 1 元、最高 1000 元，金额为整数分。创建订单不增加余额。支付宝返回官方签名付款链接；微信返回官方 `code_url`，客户端据此生成二维码。支付页面返回或客户端声称“成功”均不能入账。

支付宝须配置本商户 app_id、seller_id、RSA2 商户私钥、支付宝公钥和 HTTPS 公共通知地址。微信须配置 appid、mchid、商户证书序列号与私钥、微信支付公钥和对应序列号（或已核实的平台证书公钥/序列号）、32 字节 APIv3 密钥及 HTTPS 通知地址。配置密钥轮换须同时更新公钥及序列号；未知序列号直接拒绝，不从未验证的回调自动下载公钥。

支付宝通知检查 RSA2 签名、app/seller、订单、金额、状态及币种；微信通知先按原始字节验签并检查序列号/5 分钟时间窗口，再 AES-256-GCM 解密，检查 app/mch/订单/金额/CNY/成功状态。微信创建和查询响应同样验签。支付宝主动查询验签原始响应 JSON 子串，绑定本商户签发的请求和被查询订单；查询响应未提供 app/seller 字段时不伪造字段，而以已签发请求身份和官方响应签名为依据；通知仍强制提供 app/seller。

只有通过上述核验的成功通知或主动查单才在同一事务中更新订单、余额及唯一账本引用。订单状态比较更新、交易号唯一约束及账本引用唯一约束防止重复/并发回调入账。订单创建或查单网络失败不自动重复创建；用户可在最近订单中查询。退款、自动关单、商户对账下载和管理后台不在本次实现范围内，退款应先走支付机构商户后台，并在上线前制定余额核减与退款流程。

## 平台积分（独立账本，默认关闭）

积分与元余额是两套互不兑换的账本：元余额在 `billing_accounts` / `billing_ledger` / `payment_orders` / `billing_calls`，积分在 `credit_lots` / `credit_calls` / `credit_ledger`（迁移 `c3a1b2c3d4e5`，前驱 `b2f9e8d7c6a5`）。切换仍写 `billing_accounts.mode='platform'` 与 `model_id='credits:deepseek-flash'`，网关据此把文本调用路由到积分结算。

- **启用**：`CREDITS_DEEPSEEK_ENABLED=true` 且 `BILLING_PROVIDER_KEYS_JSON` 含 `deepseek`；缺任一项，目录为空、切换返回 503，不发起上游调用。
- **单价与上限**：输入 40 积分 / 百万 token、输出 160 积分 / 百万 token；单次上限 16,000 输入、4,096 输出；非流式、关闭思考模式、仅文本。
- **精度**：1 积分 = 1,000,000 微积分；费用 = 输入 token × 40 + 输出 token × 160，合计向上取整到 1 微积分。
- **发放与过期**：每人每北京时间自然月自动发放 500 积分，月末 00:00 过期不结转；扣费按批次到期时间先后占用。调用前按上限预留，预留 10 分钟未结算在账户读取或下次调用时释放。
- **未实现**：购买、开通、自动续费、退款、管理后台。目录中的免费 / 启航 / 补给三档 `purchaseAvailable` 恒为 `false`，价格与积分数只作展示。试运行测试积分由运维本地执行 `grant_test_qihang` 发放，不产生支付记录，不能当作已上线订阅。

## 验证边界

测试只使用临时 SQLite、现场生成的测试 RSA/AES 密钥与 `httpx.MockTransport`；没有真实收款或真实模型调用，也没有凭此宣称商业渠道已可运营。真实环境必须补充商户资质、实际模型/费率/密钥、公网 HTTPS 通知地址，并完成小额支付回调/主动查单、模型 usage、账单及余额的真实核对后再启用收款开关。
